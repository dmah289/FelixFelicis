1. Particle = 16 bytes

Mỗi particle trên GPU là 1 struct 16 bytes — hai bên C# và HLSL phải khớp byte-by-byte:

// C# — StructLayout ngăn compiler sắp xếp lại thứ tự trường
[StructLayout(LayoutKind.Sequential)]
public struct ParticleRenderData
{
    public Vector2 center;      // 8 bytes
    public float   radius;      // 4 bytes
    public uint    packedColor; // 4 bytes  ← Color 16B → uint 4B
}
// HLSL — phải khớp thứ tự và kích thước từng trường
struct ParticleData
{
    float2 center;      // 8 bytes
    float  radius;      // 4 bytes
    uint   packedColor; // 4 bytes
};

Nếu thứ tự lệch → GPU đọc sai offset → visual corruption. 16 bytes là power-of-2, nên GPU cache line (64 hoặc 128 bytes) chứa đúng 4 hoặc 8 particles — không lãng phí.

Color packing

Color của Unity = 4 float = 16 bytes. Màu particle không cần float precision (256 mức/kênh là đủ), nên pack Color32 (4 × uint8) thành 1 uint = 4 bytes. Struct giảm từ 28 bytes (8 + 4 + 16) xuống 16 bytes (−43% bandwidth).

C# pack:    (uint)(R | G<<8 | B<<16 | A<<24)

Bộ nhớ (little-endian):
byte:     [  R  ][  G  ][  B  ][  A  ]
bit:      0──7   8──15  16──23 24──31

HLSL unpack:
  R = (packed        & 0xFF) / 255.0
  G = ((packed >> 8)  & 0xFF) / 255.0
  B = ((packed >> 16) & 0xFF) / 255.0
  A = ((packed >> 24) & 0xFF) / 255.0

Color32 c = color — C# implicit conversion tự clamp float [0,1] → byte [0,255].

2. CPU → GPU: 1 memcpy mỗi frame

Loại bỏ data copies

Simulation (CPU) tạo data mỗi frame, GPU cần đọc để vẽ. Hệ thống ban đầu có 4 copies:

Ban đầu (4 copies):
SoA arrays ──COPY 1──► Provider List<T> ──COPY 2──► Drawer List<T> ──COPY 3──► SetData ──► GPU
  positions[]              list.Add(struct)       destructure→       pin + memcpy
  radii[]                                         AddParticle()→
  colors[]                                        reassemble→Add()

Hiện tại (1 copy):
SoA arrays ──ghi thẳng──► NativeArray (CPU staging) ──SetData──► GPU
                          persistent, grow-only          memcpy
Bước tối ưuCopy loại bỏCách
Bỏ Provider List<T>Copy #1Provider chỉ giữ drawer reference, không giữ data
Bỏ AddParticle() per-element loopCopy #2Drawer không giữ list riêng, nhận data trực tiếp qua NativeArray
Bỏ SetData(List<T>)Copy #3 (pin)NativeArray unmanaged — không cần GC pin

Copy còn lại: 1 memcpy trong SetData(NativeArray, 0, 0, count) — driver tự handle cache coherence, an toàn trên mọi GPU driver kể cả mobile Vulkan.

NativeArray — CPU staging buffer

NativeArray<T> nằm trên unmanaged heap — ngoài GC. So với List<T>:

List<T>NativeArray<T>

SetData()GC pin → memcpy → unpinmemcpy trực tiếp

Dùng Allocator.Persistent (sống qua nhiều frame) + UninitializedMemory (không zero-fill, sim sẽ ghi đè hết).

Tại sao dùng Cách 2, không phải Cách 3 (zero-copy)? Trên mobile Vulkan (Mali Valhall — G610, G710, G720), driver không flush CPU cache → GPU đọc stale data → particles invisible. Unity không expose memory barrier API để workaround. SetData(NativeArray) qua Unity's managed upload path — driver tự xử lý cache coherence. Chi phí: 10K × 16B = 160 KB ≈ 0.05ms — negligible.

Double buffering

CPU và GPU chạy không đồng bộ — GPU pipeline xử lý lệnh từ frame trước trong khi CPU đã chuyển sang frame tiếp. Nếu chỉ có 1 buffer, CPU ghi đè data mà GPU đang đọc:

Single buffer:                     Double buffer:
Frame N:   CPU write → A           Frame N:   CPU write → A    GPU đọc B (frame trước)
Frame N+1: CPU write → A ⚠️        Frame N+1: CPU write → B    GPU đọc A (frame N)
           GPU vẫn đang đọc A!    Frame N+2: CPU write → A    GPU đọc B (frame N+1)
           → race condition                   Không conflict ✓

Triển khai: 2 GraphicsBuffer, swap mỗi frame đầu BeginFrame:

writeIndex = (writeIndex + 1) % 2

Trong cùng 1 frame: EndFrame upload vào instanceBuffers[writeIndex], Draw bind cùng instanceBuffers[writeIndex]. Không mâu thuẫn — vì EndFrame (CPU) hoàn thành trước khi Draw record command, và GPU execute draw command sau khi upload xong. Buffer còn lại (writeIndex cũ) là buffer frame trước mà GPU pipeline có thể vẫn đang đọc — nhờ swap, CPU không đụng vào nó.

Chi phí: thêm 1 buffer (10K × 16B = 160 KB).

Color packing at Start() vs Update(): Debug sim pack color 1 lần ở Start() (cold path). Simulation thật nếu color thay đổi mỗi frame → pack trong Update vẫn rẻ hơn truyền Color 16 bytes.

Grow-only buffer

Khi particle count giảm (10K → 5K), buffer không shrink — giữ capacity 10K. args[1] = count giới hạn GPU chỉ đọc 5K đầu. Tránh tạo/hủy GraphicsBuffer liên tục → stutter.

3. GPU vẽ circle: Instancing + SDF

GPU Instancing

Bottleneck khi render nhiều particles: số draw calls, không phải số polygon. GPU Instancing vẽ cùng 1 mesh N lần trong 1 draw call. Mỗi instance dùng SV_InstanceID (GPU tự tăng 0, 1, 2...) đọc data riêng từ StructuredBuffer.

APIGiới hạnDataLý do

DrawMeshInstancedIndirectKhông giới hạnTùy ý qua StructuredBuffer✓ Đang dùng

argsBuffer (5 × uint) cho GPU biết vẽ bao nhiêu, mapping tới hardware API DrawIndexedInstancedIndirect:

[0] indexCount[1] instanceCount[2] startIndex[3] baseVertex[4] startInstance
6N000

indexCount = 6: 1 quad = 2 triangles × 3 vertices. Chỉ re-upload args khi N thay đổi.

SDF (Signed Distance Field)

GPU chỉ biết vẽ tam giác. SDF dùng 1 quad (4 vertices), fragment shader tính per-pixel:

SDF(p) = length(p) − radius
//  < 0 → inside    = 0 → edge    > 0 → outside

length(p) = √(x² + y²) — khoảng cách Euclidean từ pixel đến tâm. Trừ radius: âm = bên trong circle.

▶ SDF — di chuột trên circle để thấy giá trị khoảng cách

Anti-aliasing: fwidth + smoothstep

Nếu chỉ check sdf < 0 → ON, ≥ 0 → OFF, biên bị răng cưa. Cần gradient 1-pixel tại biên:

float fw    = fwidth(sdf);  // "1 pixel rộng bao nhiêu đơn vị SDF"
float alpha = 1.0 - smoothstep(-0.5 * fw, 0.5 * fw, sdf);

fwidth() là hardware derivative — GPU so sánh giá trị sdf giữa pixel lân cận trong block 2×2:

fwidth(sdf) = |dFdx(sdf)| + |dFdy(sdf)|
// dFdx ≈ sdf(pixel_phải) − sdf(pixel_hiện_tại)
// dFdy ≈ sdf(pixel_dưới)  − sdf(pixel_hiện_tại)

Tự động đúng cho mọi camera type và zoom level — vì đo trực tiếp trên screen space.

smoothstep(edge0, edge1, x) — đường cong Hermite (chữ S): t² × (3 − 2t). Đạo hàm = 0 tại hai đầu → gradient mượt, không "bước nhảy".

▶ Smoothstep curve — transition zone 1 pixel
alpha (opacity)SDF = 0 (edge)
AA padding: Quad phải lớn hơn circle để fragment shader có chỗ vẽ gradient. Vertex shader mở rộng thêm aaPadding = radius × 0.1 (world-space) hoặc 2.0 pixel (screen-space).

Tại sao fwidth() thay vì invTexelSize (approach SebVis)?

SebVis: saturate(0.5 - sdf * invTexelSize)Hiện tại: fwidth() + smoothstep()
Tính toánVertex shader tính invTexelSize từ unity_OrthoParamsFragment shader gọi hardware fwidth()
Camera typeChỉ orthographicMọi camera (ortho + perspective)

fwidth() đắt hơn invTexelSize (~1 instruction vs precomputed), nhưng đúng cho mọi trường hợp mà không cần biết camera type.

5. Shader

CBUFFER + StructuredBuffer

CBUFFER_START(ParticleUniforms)
    float4x4 WorldToClipSpace;   // VP matrix, per-camera
    float2   ScreenSize;         // viewport size, per-camera
    int      useScreenSpace;     // 0 = world-space, ≠0 = screen-space
    uint     InstanceOffset;     // offset vào StructuredBuffer
CBUFFER_END

StructuredBuffer<ParticleData> InstanceData;  // particle data

CBUFFER explicit: D3D11 tự gom loose globals vào $Globals. Vulkan SPIR-V compiler không có cơ chế này → binding sai.

cmd.SetGlobal*() thay vì material.Set*(): material.Set*() là immediate mode — Vulkan descriptor set caching có thể khiến property changes chưa visible khi GPU execute. cmd.SetGlobal*() ghi vào command stream → GPU đọc đúng lúc.

material.Set*() (immediate)              cmd.SetGlobal*() (deferred) ✓
┌──────────────────────┐                ┌──────────────────────┐
│ CPU: set property    │                │ Record: ghi vào cmd  │
│ GPU: đọc khi nào?    │ ← race        │ Execute: GPU đọc     │ ← deterministic
│      có thể stale    │                │          đúng lúc    │
└──────────────────────┘                └──────────────────────┘

Trên D3D11 Editor, driver tự sync material state trước mỗi draw call nên material.Set*() vẫn hoạt động — lỗi chỉ lộ trên Vulkan build.

Vertex shader

v2f vert(appdata v, uint instanceID : SV_InstanceID)
{
    ParticleData p = InstanceData[instanceID + InstanceOffset];

    float2 aaPadding = useScreenSpace ? 2.0 : p.radius * 0.1;
    float2 localVert = v.vertex.xy * (p.radius * 2 + aaPadding);
    float3 worldPos  = float3(localVert + p.center, 0);

    o.clipPos  = WorldToClipPos(worldPos);
    o.localPos = localVert;    // dùng cho SDF
    o.radius   = p.radius;
    o.color    = UnpackColor(p.packedColor);
}
  1. Đọc particle data: InstanceData[instanceID + InstanceOffset]
  2. Tính quad size: diameter = radius × 2, thêm aaPadding cho gradient biên
  3. Scale vertex: localVert = v.vertex.xy × (diameter + aaPadding)
  4. Dịch về vị trí particle: worldPos = float3(localVert + center, 0)
  5. Transform: clipPos = WorldToClipPos(worldPos)
  6. Pass cho fragment: localPos (dùng cho SDF), radius, color (unpacked)

WorldToClipPos hỗ trợ 2 mode:

  • World-space (useScreenSpace = 0): mul(WorldToClipSpace, float4(worldPos, 1)) — nhân VP matrix
  • Screen-space (useScreenSpace ≠ 0): worldPos.xy / ScreenSize × 2 − 1 — map pixel coords → NDC

Fragment shader

half4 frag(v2f i) : SV_Target
{
    float sdf   = length(i.localPos) - i.radius;    // signed distance
    float fw    = fwidth(sdf);                       // 1 pixel width
    float alpha = 1.0 - smoothstep(-0.5*fw, 0.5*fw, sdf);
    return half4(i.color.rgb, i.color.a * alpha);
}

3 instruction làm mọi thứ: tính khoảng cách → đo pixel width → tạo gradient.

VP matrix

Matrix4x4 vp = GL.GetGPUProjectionMatrix(cam.projectionMatrix, true)
             * cam.worldToCameraMatrix;
  • worldToCameraMatrix = View (V) — world → camera-local
  • projectionMatrix = Projection (P) — camera-local → clip space
  • GL.GetGPUProjectionMatrix(..., true) — chuyển P sang GPU-native: Y-flip (Vulkan), depth range (D3D [0,1] vs GL [−1,1]). true = render vào render texture
  • Kết quả: VP = P × V — nhân theo thứ tự này vì HLSL mul(VP, position) = VP × position

6. URP Integration

Tổng quan

ScriptableRendererFeature (composition root, sống qua domain reload) ├─ Create() → tạo drawer + pass, đăng ký provider ├─ AddRenderPasses() → enqueue pass mỗi frame └─ Dispose() → giải phóng GPU resources ScriptableRenderPass (bridge URP ↔ IInstanceDrawer) ├─ RecordRenderGraph() → Unity 6+ RenderGraph (AddUnsafePass) └─ Execute() → Legacy Compatibility Mode

ParticleRendererFeature (ScriptableObject) là composition root — tạo drawer + pass, đăng ký provider:

public override void Create()
{
    ReleaseResources();   // URP gọi Create() nhiều lần → prevent leak
    drawer = new ParticleDrawer();
    renderPass = new ParticleRenderPass(drawer);
    ParticleProvider.Register(drawer);
}

RenderGraph path

AddUnsafePass (không phải AddRasterPass) vì DrawMeshInstancedIndirect là raw command buffer operation.

using var builder = renderGraph.AddUnsafePass<PassData>("ParticleRendering", out var passData);

builder.UseTexture(activeColorTexture, AccessFlags.ReadWrite);  // alpha blending
builder.UseTexture(activeDepthTexture, AccessFlags.Read);
builder.AllowPassCulling(false);  // RenderGraph không detect procedural draw

builder.SetRenderFunc(static (PassData data, UnsafeGraphContext context) =>
{
    // Explicit bind — AddUnsafePass KHÔNG auto-bind render targets
    context.cmd.SetRenderTarget(data.colorTarget, data.depthTarget);
    var cmd = CommandBufferHelpers.GetNativeCommandBuffer(context.cmd);
    data.drawer.Draw(cmd, data.camera);
});

PassData

Class, không phải struct — RenderGraph pool instances nội bộ, gán qua out parameter. Struct sẽ bị copy, mất reference. RenderGraph pool PassData sau frame đầu → zero heap allocation từ frame thứ 2. Static lambda → zero closure capture → zero GC.

ScriptableRendererFeature (ScriptableObject) không thể reference MonoBehaviour trực tiếp. 3 phương án:

ParticleProvider — static class làm cầu nối:

public static class ParticleProvider
{
    private static ParticleDrawer instance;
    internal static IInstanceWriter<ParticleRenderData> Writer => instance;

}

Simulation chỉ thấy IInstanceWriter<T>, render pass chỉ thấy IInstanceDrawer. Cùng 1 ParticleDrawer, nhưng consumer không biết nhau.

Lazy material

Resources.Load<Shader>("ParticleDraw") — load trực tiếp. Shader.Find() chỉ tìm shader referenced bởi material asset hoặc Always Included Shaders → trả null trên build (vì material được tạo runtime). EnsureMaterial() retry mỗi frame, thành công rồi thì chỉ check null — 1 branch.

11. Debug sim

ParticleDebugSim — MonoBehaviour test rendering pipeline:

  • Start(): pre-allocate tất cả arrays (positions, velocities, radii, packedColors). PackColor() gọi 1 lần ở đây (cold path), không ở Update (hot path)
  • Update(): di chuyển particles (bounce khi chạm biên), ghi thẳng vào NativeArray qua ParticleProvider.Writer
  • Runtime Inspector thay đổi particleCount không có hiệu lực — cần restart Play
